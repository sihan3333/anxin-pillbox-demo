# 拍一拍核对 设计文档

- 日期：2026-10-25
- 状态：草稿，待确认
- 所属：安心药箱 AI 能力扩展，第一项。第二项「会说话的服药助手」另写

## 1. 为什么做

安心药箱现在唯一真正用到大模型的地方是「AI 整理医嘱」，在子女端，一次性的。父母每天吃药的环节里没有 AI。

父母端最危险的错误是**拿错药**：两盒药颜色相近、格子放错、换了包装。现在的吃药指引只靠「第几格 + 盒子颜色 + 药片样子」描述，父母拿没拿对，产品不知道。

拍一拍核对让 AI 进入每天的服药环节：吃之前把药盒对着手机拍一下，产品告诉父母「对了」还是「不对，该吃哪一盒」。

## 2. 目标、非目标、反目标

**目标**

1. 父母在吃药指引页能拍药盒，几秒内得到「对了 / 不对 / 不在清单 / 看不清」之一的答复，答复会读出来。
2. 拿错药时当场拦下，并告诉父母正确的是第几格、什么颜色的盒子。
3. 子女端能看到核对记录；拿错药时子女收到提醒。

**非目标**

1. 不识别散装药片、药板上的药片样子。第一版只读药盒上印的字。
2. 不核对吃了几片、有没有吃下去。
3. 不回答药品相关问题，那是第二项「会说话的服药助手」。
4. 核对不是必经步骤。不拍照也能照常按「我吃好了」。

**反目标：出现这些，即使功能能跑也算失败**

1. **把错药说成「对了」。** 这是唯一不可接受的错误，评测集里必须为 0。
2. 网络或模型出问题时卡住吃药流程。
3. 照片被保存或被用于核对以外的用途。

## 3. 原则：模型只读字，规则来判断

沿用「模型理解、规则决定」：

1. **模型**只做一件事：把药盒上印的药名、规格原样抄下来，看不清的标「看不清」。模型**不知道**这一顿该吃什么，提示词里不给计划，避免它被计划带偏、「看成」想看的字。
2. **规则**拿模型抄下来的字，与药品清单比对，决定说什么。
3. 拿不准一律归到「看不清」，绝不归到「对了」。

## 4. 方案选择

| 方案 | 做法 | 取舍 |
|---|---|---|
| A. 接能看图的大模型（**选定**） | 通义千问 VL，经现有 Cloudflare Worker 中转 | 中文小字、反光、倾斜识别好；需要新 key，按次少量计费 |
| B. 浏览器内开源文字识别 | Tesseract.js 等，本地跑 | 免费、照片不出手机；中文小字和反光药盒准确率明显差，「看不清」会很多 |
| C. 让模型直接判断对不对 | 把计划和照片一起给模型，让它答「对/不对」 | 实现最简单；模型会被计划带偏，误判「对了」风险最高，违反反目标 1 |

选 A 的依据：用户确认用能看图的大模型，并确认用通义千问 VL。C 因反目标 1 直接排除；B 作为备选，不进第一版。

## 5. 怎么用

### 5.1 子女登记药品时：记下「药盒上的名字」

药品清单里的 `name` 是家里人的叫法，比如「降压药」；药盒上印的是通用名，比如「苯磺酸氨氯地平片」。核对必须拿药盒上的名字比。

1. 每种药新增字段 `boxName`（药盒上的药名）和可选的 `boxSpec`（规格，如「5mg」）。
2. 子女在添加药品页拍药盒照片时，调用同一个识别接口，把读到的药名和规格**预填**进这两个字段，子女可以改。现有的「拍药盒照片」入口复用，不新增按钮。
3. 也可以手动填写。没填 `boxName` 的药，父母端不显示「拍一下核对」。
4. 示例数据里的两种药补上 `boxName`，如「苯磺酸氨氯地平片」和「盐酸二甲双胍片」，`name` 的「（示例）」不变。

### 5.2 父母吃药时：拍一下核对

在吃药指引页（当前这一种药的卡片下方）加一个按钮「拍一下，看拿对没有」。

1. 点按钮 → 调起后置摄像头拍照（桌面浏览器则是选图）。
2. 显示「正在看…」，最长等 10 秒。
3. 出结果，大字显示并读出来，四种答复见 5.3。
4. 结果只影响提示，不改服药状态。父母仍然要按「我吃好了」。

### 5.3 四种答复和规则

设模型读到的药名集合为 R，这一顿当前这一种药为 m，这一顿全部药为 D，全部清单为 L。

| 情况 | 判断规则 | 父母看到并听到 | 子女端 |
|---|---|---|---|
| 对了 | R 中有一个与 m.boxName 匹配；m 填了 boxSpec 时，必须读到规格且一致 | 「对了，这是{m.name}，吃{m.dose}。」 | 记录「拍照核对：对了」 |
| 也是这一顿的 | R 与 m 不匹配，但与这一顿 D 里的另一种药 x 匹配 | 「这也是这一顿要吃的{x.name}，可以吃，吃{x.dose}。吃完别忘了第{m.slot}格的{m.name}。」 | 只记录，不推送 |
| 不对 | R 与 D 都不匹配，但与清单 L 里的另一种药 x 匹配 | 「不对，这是{x.name}，先别吃。现在该吃的是第{m.slot}格、{颜色}盒子的{m.name}。」 | 记录「拍照核对：拿错了」，并推送提醒 |
| 不在清单 | R 读到了药名，与 L 里任何一种都不匹配，且 L 里每种药都填了 boxName | 「这盒药不在清单里，先别吃。可以问一下女儿。」 | 记录并推送提醒 |
| 看不清 | 模型标看不清；读到的药名为空；同时读到两个以上不同药名；药名匹配但 m 有 boxSpec 而规格没读到；或 L 里有药没填 boxName、导致无法断定「不在清单」 | 「看不清，请把药盒正面对着手机，再拍一次。」 | 只记录 |

**匹配规则**（宁严勿松）：

1. 两边都去掉空格、标点、括号内容后，**完全相等**才算匹配。
2. 不做模糊匹配，不忽略剂型和修饰词。「硝苯地平片」和「硝苯地平控释片」、「氨氯地平」和「左旋氨氯地平」都算**不匹配**。
3. 规格不一致（5mg 对 10mg）算不匹配，走「不对」或「不在清单」。
4. 一张照片里出现两盒不同的药，算「看不清」，提示一次只拍一盒。

**连续看不清**：同一种药连续 2 次看不清，第 2 次答复改为「还是看不清，没关系，按照片和格子号吃就行。拿不准就按『我需要帮忙』」，不再要求重拍。

**接口失败**（断网、超时、额度用完）：答复「现在核对不了，按照片和格子号吃就行」，不算看不清，不推送。

### 5.4 子女端

1. 每顿服药记录下显示核对结果，如「08:00 降压药 · 拍照核对：对了」。
2. 「不对」和「不在清单」发通知，标题「⚠️ 妈妈可能拿错药了」，正文写明拿到的是什么、该吃的是什么，建议打个电话。

## 6. 模型接入

1. Cloudflare Worker 新增一条路由，转发到阿里云百炼的通义千问 VL，密钥存为 Worker 的环境变量。密钥不进前端代码、不进仓库。Worker 源码不在仓库里，沿用医嘱整理时的做法：施工方写好新版 Worker 代码，放进仓库的 `worker/` 目录备查；由用户在 Cloudflare 后台粘贴部署并填 key，施工方一步步带着做。前端先用一个模拟接口开发和测试，部署完成后再联调。
2. 前端发送一张压缩后的 JPEG。现有 `readPhoto` 把图缩到 360px，用于展示可以，识别不够；识别用的图长边约 1024px。
3. 模型输出 JSON：

```json
{ "readable": true, "names": ["苯磺酸氨氯地平片"], "specs": ["5mg"], "note": "" }
```

4. 提示词要点：只抄药盒上印的药品名称和规格，一字不改；看不清、被挡住、只露出一半的就不写，`readable` 置为 false；不要根据颜色、图案或常识推测药名；照片里不是药盒也置为 false。
5. 照片只用于这一次请求，前端不保存，Worker 不记录。

## 7. 评测

沿用医嘱整理评测的做法：先建评测集，再按坏例迭代。

**指标，按重要性排序**

1. **误判「对了」率**：照片里不是该吃的药，却答了「对了」的比例。必须为 0，任何一轮出现都要先修再继续。
2. **该对的认对率**：清晰拍摄的正确药盒，答「对了」的比例。目标 90% 以上。
3. **看不清率**：清晰照片被答成「看不清」的比例，越低越好，用来衡量是否保守过头。

**评测集覆盖的情况**

1. 正确药盒，正面清晰
2. 正确药盒，有倾斜、反光、局部遮挡、侧面或竖排
3. 清单内的另一种药（真正的拿错）
4. 名字相近的药：同成分不同剂型、同成分不同规格、只差一两个字
5. 清单外的药
6. 只有药板、没有药盒
7. 模糊、过暗、只拍到一角
8. 一张照片两盒药
9. 不是药盒的照片

**照片来源**（用户决定）：

1. **以仿真药盒图为主。** 由施工方用程序生成：真实通用名和规格，印在自拟品牌、自拟配色的包装上，不仿任何药企的真实包装。再叠加倾斜、反光、模糊、遮挡、过暗等变化，覆盖上面 9 类情况。每类至少 10 张，总数不少于 120 张，误判「对了」率为 0 才有分量。
2. **用户补充几张家里真药盒的实拍。** 单独标为「实拍」，在报告里分开统计，用来检验仿真图上的成绩能不能迁移到真照片。公开前遮掉处方标签、姓名、医院等个人信息。
3. 「用示例药盒试一试」的三张图用仿真图。

划分沿用 seed / dev / holdout，holdout 只在最后跑一次。产出评测集文件、运行页和数据分析报告，放在 `eval/` 下，与医嘱整理评测并列。

## 9. 设计时替用户拿的主意，请确认

1. **规格读不到就不说「对了」。** m 填了规格时，必须读到一致的规格才答「对了」，否则答「看不清」。这样认对率会低一些，但避免把 10mg 当成 5mg，符合反目标 1。
2. **拍到这一顿的另一种药不算拿错。** 单独答「也是这一顿要吃的」，不推送子女，避免误报。
3. **清单里有药没填药盒名时，不下「不在清单」的结论**，改答「看不清」，避免把清单里的药说成清单外、误推送。
4. **只改 Demo，不改 `mvp/` 目录。**
