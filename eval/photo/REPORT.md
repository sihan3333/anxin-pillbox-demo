# 拍一拍核对 · 评测报告

- 日期：2026-10-25
- 模型：通义千问 qwen3-vl-plus（阿里云百炼，经 Cloudflare Worker 中转）
- 评测集：photo-v1，158 张仿真药盒图，14 类情况
- 结论：最终一轮 **误判「对了」0/107**，158 张全部答对；清晰正确药盒认对 16/16

## 1. 评什么

父母吃药前拍一下药盒：模型只抄药盒上的通用名、规格，并报告拿不准、药盒位置；规则拿这些和药品清单比对，给出五种答复之一。

| 指标 | 含义 | 要求 |
|---|---|---|
| 误判「对了」 | 照片里不是该吃的药，却答「对了」 | **必须为 0** |
| 清晰正确药盒认对率 | 第 1 类清晰照片答「对了」的比例 | 90% 以上 |
| 清晰照片「看不清」率 | 第 1 类清晰照片被答成「看不清」 | 越低越好 |
| 接口失败 | 重试一次后仍拿不到结果 | 记录，答复为「现在核对不了」 |

每张图标注了「可接受的答复」。例如模糊照片里的正确药盒，答「对了」或「看不清」都可接受；名字相近的药，只接受「不在清单」或「看不清」。

## 4. 坏例和修法

**坏例 1：关键字被挡住，模型把药名「补完整」。** 第 2 轮 4 张。

- 现象：盒子是「盐酸二甲双胍缓释片」，「缓释」被手指挡住，模型读成「盐酸二甲双胍片」，正好是清单里的药，规则答了「对了」。「左旋」「肠溶」同理。
- 根因：模型会跳过看不见的字，再凭常识拼成一个常见药名。
- 修法：提示词要求被挡的字一个字写一个 □，并报告 sure；规则看到 □ 或 sure 不为 true，一律答「看不清」。
- 结果：H2 的 4 张误判全部变为「看不清」。

**坏例 2：远拍时模型「确定地」读错规格。** 第 2、3 轮各 1 张。

- 现象：远处一盒 10mg 的苯磺酸氨氯地平片，规格那行只有约 5 个像素高，模型连续 4 次都读成「5mg」，并且自称 sure。
- 根因：字小到看不清时，模型用常见规格补上，而且自己意识不到。靠模型自报拿不准，在这里失效。
- 修法：让模型报告药盒在照片里的位置，规则判断药盒最长边不到照片的 30%，就不看读到了什么，直接请父母「拿近一点再拍」。
- 代价：远拍的正确药盒也会被要求重拍，H4 里 4 张正确药盒都答「看不清」。用一次重拍换掉一次可能的拿错药，符合反目标。

**坏例 3：模糊照片上，模型输出的 JSON 多了一个 `}`。** 第 3、4 轮 1–5 张。

- 现象：`"specs":["□mg"]},"box":…`，解析失败，答复变成「现在核对不了」。
- 影响：不会误判，但影响可用性。
- 修法：Worker 只修这一种已知格式错误，修不好仍按失败处理。

## 5. 局限

1. **全部是仿真图。** 真实药盒的字体、反光、弧面、印刷质量都更难，这里的成绩只能说明流程和规则有效，不能代表真实拍照的准确率。家里真药盒的实拍会单独标注、分开统计。
2. **holdout 不是严格留出。** 为观察每轮改动的整体影响，holdout 每轮都跑了，改动依据的坏例虽然大多来自 seed / dev，但 holdout 里也出现过同类坏例。第 5 轮的 holdout 46/46 应视为偏乐观的估计。
3. **模型输出有随机性。** 第 4 轮复跑答复一致，但接口失败数在 1–2 之间浮动。
4. **药盒位置判断依赖模型。** 30% 阈值是按本评测集定的，真实使用中需要按实拍数据再调。
