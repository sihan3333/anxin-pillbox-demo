# 安心药箱 · 医嘱整理评测集设计

更新：2026-10-25 · 文件：`rx_cases_v2.json`（120 条）· 运行：`eval/index.html` · 分析报告：`eval/report.html`

## 1. 评测什么

子女录入新药时，把医嘱、药盒用法或一句口述交给 AI，整理成 4 个字段：**药名、每次吃多少、具体几点、怎么吃**。

对用药来说，最危险的不是"没整理出来"，而是"编出来"。所以评测的第一指标是**编造率**：原话里没写的字段，AI 却填了内容。

## 2. 数据从哪来

| 来源类型 | 条数 | 写法特点 |
|---|---|---|
| 子女口述 | 81 | 口语、省略、"那个降压的药"、"早上吃" |
| 处方 / 说明书 / 药盒标签 | 36 | 通用名 + 规格、qd / bid / qn 等缩写、"一次1~2片"、英文处方 |
| 语音转写 | 3 | 语气词、没有标点 |

全部由开发者按真实处方、说明书和子女口述的写法编写，**不含真实患者信息**。上线前需要补充真实医嘱（见第 7 节）。

## 3. 数据集划分

| 划分 | 条数 | 用途 | 规则 |
|---|---|---|---|
| seed | 40 | 种子集，覆盖常见写法 | 不改标注 |
| dev | 50 | 用来发现坏例、定位原因 | 可以反复看 |
| holdout | 30 | 验证改动是否泛化 | **不看具体用例**，只看汇总分数 |

dev 和 holdout 覆盖相同的陷阱类型，但用不同的药名和说法，防止"针对用例改规则"造成的虚高。

## 4. 覆盖维度：陷阱类型

每条用例用 `traps` 标注它考察的难点，一条可以有多个。

| 类别 | 陷阱 | 正确做法 |
|---|---|---|
| 时间 | 只有频次（一日三次、早晚各一次、bid） | "具体几点"留空，不能推成 08:00 / 12:00 / 18:00 |
| 时间 | 间隔推时刻（每 8 小时） | 留空 |
| 时间 | 中文时刻（下午三点、晚上十点半） | 换算成 15:00、22:30 |
| 时间 | 多个时刻、模糊时刻（大概六点） | 全部列出；说了钟点就填 |
| 吃法 | 时段不是吃法（早上吃、晚上吃、晨服、qn） | "怎么吃"留空，时段不算吃法 |
| 剂量 | 分时段剂量（早上一片晚上半片） | "每次吃多少"留空，不能挑一个 |
| 剂量 | 剂量范围（一次 1~2 片）、剂量递减、剂量未说 | 留空 |
| 剂量 | 剂量单位（mg、g、毫升、单位、滴、袋、吸、丸、支）、半片 | 数字和单位都要对 |
| 药名 | 没有药名（说明书片段）、口语药名（护心的药）、错别字、英文 | 没说就留空；口语名保留原说法 |
| 语义 | 按需、停药、否定、条件用药、疗程、每周 / 隔日 | 不编造时刻和吃法 |
| 噪声 | 说不清（按医生说的吃）、口语噪声、长句 | 只取明确的部分 |

## 5. 标注规范

1. **药名 `name`**：原话里的药品叫法，可接受多个关键词，任一出现即算对；没提药名时为空。
2. **每次吃多少 `dose`**：数字 + 单位；"一片""1片"等价，"半片"记 0.5 片；只写一天总量、剂量随时段不同、给范围、写"按单子来"时为空。
3. **具体几点 `times`**：24 小时制数组，只记原话里说出的钟点；"早上""饭后""一日三次""每 8 小时"一律为空数组。
4. **怎么吃 `method`**：饭前、饭后、随餐、睡前、空腹、温水送服、舌下含服、外用等吃法关键词；早上、晚上等时段不算吃法，为空。
5. **可选字段 `optional`**：合理的人可能填也可能不填的字段（例如"口服"），填对或留空都算对，但填错仍算错。

有争议的用例先按规范标注，在标注说明里写清理由，再由第二人复核；两人不一致的用例不进入 holdout。

## 6. 判分与指标

每条用例的每个字段判为四类之一：

| 判定 | 含义 |
|---|---|
| 对 | 与标准答案一致；应留空且留空 |
| 编造 | 应留空却填了 |
| 填错 | 应填，但填的内容不对 |
| 漏填 | 应填却留空 |

| 指标 | 计算 | 上线门槛 |
|---|---|---|
| **编造率**（第一指标） | 编造字段数 ÷ 应留空字段数 | ≤ 2% |
| 4 字段全对率 | 4 个字段都对的条数 ÷ 总条数 | ≥ 95% |
| 字段准确率 | 判为"对"的字段数 ÷ 总字段数 | ≥ 98% |
| 核对误删 | 规则核对去掉的、本来正确的字段数 | 0 |

同一次大模型输出分两种方式计分：**原始输出**和**经过规则核对后**，用来看护栏本身是否有效、是否误伤。规则版（没连上大模型时的兜底）单独计分。

## 7. 坏例处理流程

1. **发现**：在 dev 上跑评测，列出所有没有全对的用例；线上则收集子女在 AI 整理后又改动过的字段。
2. **归类**：按陷阱类型和判定（编造 / 填错 / 漏填）归类，看是模型问题、核对规则问题还是标注问题。
3. **修复**：模型问题改提示词，越界问题加规则核对，标注问题修标注并记录。
4. **回归**：dev、seed 全量重跑，确认没有新的退步；再看 holdout 汇总分数，确认改动能泛化。
5. **入集**：修复过的坏例保留在评测集里作回归用例；线上新坏例脱敏后补进 dev。
